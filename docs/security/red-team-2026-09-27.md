# Red team review, 2026-09-27

WhisperWoof reads and keeps what you copy and what you say, including passwords that pass through the clipboard. This review attacked the whole app to find every way that data could leak, be stolen or be misused, and fixed what it found.

**Result:** about 75 distinct findings once duplicates between the reviews are merged: 3 critical, 14 high, and the rest medium, low or informational. Every critical and high finding is fixed or mitigated in this change, and so are almost all medium ones. What's left needs a decision or an account only you have. It's listed under [What still needs you](#what-still-needs-you).

## How it was done

Six reviews ran in parallel, one per attack surface. Each finding was then checked against the code before anything was changed:

| Area | What was attacked |
|---|---|
| Electron shell | Windows, navigation, the ~410 IPC channels, preload, CSP, updater, packaging |
| Clipboard and typed text | Password-manager markers, secret detection, paste/restore, text monitor, logs, deletion |
| Encryption (vault) | Key hierarchy, WWENC1, SQLCipher, Touch ID helper, lock/unlock, migrations, inbox |
| Actions and outbound data | MCP plugins, automation, webhooks, Telegram, settings import/export, OAuth, API keys |
| Local servers and supply chain | whisper/llama/sherpa servers, child processes, downloads, native helpers, entitlements |
| Files and storage | Path trust, SQL, deletion and retention, file permissions, temp files |

The worst findings were proven, not just read. The upstream sherpa-onnx server was built and crashed with one message, the Linux package was built and its fuses read back, and a "deleted" password was found in the database file.

## Who the attacker is

| Attacker | Example |
|---|---|
| A web page you visit | Talks to `127.0.0.1` servers; puts text on your clipboard |
| Someone on the same Wi-Fi | Connects to any port the app opens on all interfaces |
| Content that reaches the app | Copied text, a calendar invite, an update's release notes, a Telegram message |
| A person at your locked Mac | Knows your Mac password, not WhisperWoof's |
| Another program running as you | Wants WhisperWoof's Accessibility and Microphone permissions |
| Another account on the same computer | Reads files that aren't private |
| The network or a compromised release | Swaps a downloaded binary or model |

Malware that already runs as you *while WhisperWoof is unlocked* stays out of scope, as the encryption design says (§4.8). Still, several fixes below make that malware's job harder.

## Findings and what changed

Severity is the original rating after verification. Status: **Fixed** = the attack no longer works; **Mitigated** = much harder, with a stated remainder; **Open** = needs you.

### Critical

| # | Finding | Status |
|---|---|---|
| C1 | **A password copied from a password manager ended up in clipboard history.** After a dictation, the paste code put your earlier clipboard back as plain text about 0.6 s later. The "concealed" marker was gone, so the 500 ms clipboard poll saw a new copy and saved the password. This happened by default on macOS, every time. Other clipboard managers and Windows cloud clipboard also received it unmarked. | **Fixed.** A password manager's copy is never put back, and a restored copy is never recorded again (`clipboard.js` `_shouldRestoreClipboard`, `_restoreClipboard`). Regression test in `paste-accessibility.test.ts`. |
| C2 | **The Parakeet / live-dictation speech servers listened on every network interface, and one message could overflow the heap.** Upstream sherpa-onnx binds `0.0.0.0` with no option to change it. The offline server also copies audio into a buffer sized by a length the client announces, without checking it. Anyone on the same Wi-Fi, or any web page (browsers may open `ws://127.0.0.1`), could send it. Built from upstream v1.13.4, the server **segfaulted on a single message**. | **Fixed.** `resources/patches/sherpa-onnx-v1.13.4-websocket-loopback.patch`: listen on 127.0.0.1 only, refuse handshakes that carry an `Origin` (every browser sends one, the app never does), and check every size against the buffer. `download-sherpa-onnx.js` builds the patched servers from source (`scripts/lib/sherpa-ws-patch.js`) and deletes upstream's instead of shipping them. Verified on Linux: the patched build refuses all attacks and still transcribes. |
| C3 | **Any page in any window could use all ~410 IPC channels**: API keys, clipboard history, paste, the vault, plugins. No handler checked who was calling. The control panel also let any local `file://` page load with the app's preload. | **Fixed.** `bridge/app-guard.js` + `app-origin-pure.js`: every handler first checks that the sender is the app's own `index.html` (or the dev server in development). Every window refuses navigation elsewhere, new windows and `<webview>`, and only http(s)/mailto links open outside. Permissions go only to the app's page. |

### High

| # | Finding | Status |
|---|---|---|
| H1 | Windows and Linux password-manager markers were ignored (KeePass, Bitwarden, 1Password: `ExcludeClipboardContentFromMonitorProcessing`, `CanIncludeInClipboardHistory=0`, `CanUploadToCloudClipboard=0`; KeePassXC's `x-kde-passwordManagerHint`). | **Fixed.** `clipboard-pure.js` `isPrivateClipboard`, per platform, and treats a copy as private when the check fails. Also covers older macOS markers (1Password 7, KeeWeb, TypeIt4Me, Keyboard Maestro). |
| H2 | Turning clipboard monitoring off didn't survive a restart: the app captured again while Settings still said "off". | **Fixed.** Saved in main (`clipboardCapture.monitor`), read at launch. A one-time migration honors an "off" saved by older versions. |
| H3 | No secret detection: API keys, tokens, private keys, recovery phrases and card numbers copied from any app were kept forever. Copies made inside a password manager were kept too. | **Fixed.** `sensitiveKind` skips known key formats (OpenAI/Anthropic, AWS, GitHub, GitLab, Slack, Stripe, Google, npm, Hugging Face, JWT, PEM private keys), 12–24-word BIP39 phrases, Luhn-valid card numbers and password-shaped words. Nothing is kept while a password manager is in front. Tested for false positives on URLs, paths, hashes, UUIDs and code names. |
| H4 | Electron fuses at their defaults: another program could run WhisperWoof's binary with `ELECTRON_RUN_AS_NODE` or `NODE_OPTIONS`, or attach `--inspect`, and inherit its Accessibility and Microphone permissions. | **Fixed.** `scripts/after-pack-adhoc-sign.js` flips the fuses *before* signing (electron-builder's own option flips them after, which would break the ad-hoc signature). Verified on the packaged Linux build: stock Electron runs JS under `ELECTRON_RUN_AS_NODE=1`, WhisperWoof no longer does. |
| H5 | `.env` injection: a key value containing a newline added lines to `userData/.env`, including `NODE_OPTIONS`, `PATH` or `DYLD_INSERT_LIBRARIES`, which every child process inherits. | **Fixed.** Values lose CR/LF, only known names are read back from `.env`, and the file is written 0600. |
| H6 | "Transcribe a file" (cloud and bring-your-own-key) read any path and uploaded it to any URL, plain http included. That's a one-call way to take `~/.ssh/id_rsa`. | **Fixed.** `user-audio-file.js`: only an audio file (checked after resolving symlinks) is read, and BYOK requires HTTPS or a genuinely private host. |
| H7 | llama-server: CORS echoed any origin, and there was no key, so any web page (or a DNS-rebinding one) could drive the model and read `/slots`. | **Fixed.** A random key per launch, passed in the environment (not argv), is required on every request. `--no-slots`, `--no-webui`. Verified against llama.cpp b11211. |
| H8 | whisper-server: `Access-Control-Allow-Origin: *`, so any web page could POST `/inference` or `/load` a model path (and crash the server). | **Fixed.** A random `--request-path` per launch puts every route under an unguessable prefix. Verified against whisper.cpp 0.0.10. |
| H9 | Downloaded binaries and models were checked only by size, and redirects could downgrade to http. | **Mitigated.** https on every hop, and a SHA-256 check before a file is moved into place, using the GitHub asset `digest` when the release has one. Remainder: that digest comes from the same GitHub response, and models have no pinned hashes. |
| H10 | The vault could be turned off, or destroyed, by planting `vault/migration.json` while locked. | **Fixed.** The journal is authenticated with a key from the master key. See [Encryption](#encryption-vault). |
| H11 | DevTools was available on the lock screen in release builds, and a page could cancel its own reload on unlock. | **Fixed.** DevTools is off in release windows. Pages can't veto a reload. Main reloads every other window on lock. A release build refuses to start with Chromium remote debugging. |
| H12 | Deleting a History item didn't erase it: SQLite keeps freed pages, and FTS5 keeps deleted words in its index. | **Fixed.** `db-erase.js`: `secure_delete` on both connections, FTS5 `secure-delete`, and a one-time index rebuild and `VACUUM` for what was deleted before. The WAL is checkpointed after bulk deletes. A test proves the "deleted" password was on disk before and isn't now. |
| H13 | `openExternalUrl` had no scheme check (`file:`, `smb:` and custom schemes can launch apps). | **Fixed.** http(s) and mailto only. |
| H14 | The text monitor watches the field you dictated into for 30 s. It read password fields and terminals, logged whole field contents, and saved "style examples" (500 characters of whatever was in the field) that nothing used, including in settings exports. | **Fixed.** Password fields are refused in all three native monitors (AXSecureTextField, UIA IsPassword, ATSPI PASSWORD_TEXT). Terminals and password managers aren't watched. Logs keep only line type and length. Style examples aren't recorded any more, existing ones are deleted, and they're gone from export. |

### Medium (fixed unless noted)

- **Password-marker race:** the marker check and the read were separate pasteboard calls. The marker is now checked again after the read.
- **Auto-learn and secrets:** an edit containing a secret-looking word teaches nothing. Before, it could add a password to the Dictionary, which is sent to cloud speech-to-text as a hint.
- **Log redaction** now covers `data`, `args`, `corrections`, `stdout` and more, including values nested under them. Log files are 0600, and `userData` is 0700.
- **Audio id path traversal:** `save-transcription-audio` built a file name from the id the page sent (`../../x`). Ids must be integers.
- **Notes folder:** the page could set any folder, then write or trash `.md` files there (a repo's `AGENTS.md`, `~/.claude/CLAUDE.md`). Only the native folder dialog sets it now. `*.md` symlinks that lead out of the folder aren't listed.
- **Deleting a voice entry** from History now also deletes its transcript and recording.
- **Telegram companion bot** answered anyone who found it. `TELEGRAM_ALLOWED_CHAT_IDS` is now required; others only learn their own chat id. It no longer reveals the inbox path or echoes API errors, and audio length and size are capped.
- **`.env` in the app bundle:** `extraResources` shipped the repo-root `.env`, so a builder's API keys would reach every user. Removed.
- **Private-host check:** `10.attacker.com` counted as "private" and got plain http. Only literal private IPs, `localhost` and `.local` count now.
- **Webhooks:** plain http only to this computer or the LAN, redirects aren't followed, secrets never reach the page, and the log shows only the host.
- **Temp files:** private `mkdtemp` folders with 0600 audio instead of guessable `/tmp` names (including the KWin script, which KWin executes). ffmpeg reads only `file` and `pipe` (no http/HLS tricks in imported media).
- **Startup "kill stale servers"** killed any process named like `llama-server`, the user's own included. It now matches only the app's binaries.
- **Child processes** no longer inherit your cloud API keys, tokens or `LD_PRELOAD` / `DYLD_INSERT_LIBRARIES`.
- **Release notes** were injected as raw HTML. They're rendered as React elements from a short allow-list (`SafeHtml.tsx`).
- **CI:** `ci.yml` is read-only; the two third-party actions with write access are pinned to commits, and Dependabot updates them.
- **Search:** FTS5 syntax in a query (`don't`, `C++`, `raw_text:x`) broke search or changed its meaning. Words are now quoted.
- **Other fixes:** `prepare-action` only talks to a local model, AppleScript gets app names as data (no injection), and entry templates no longer interpret `$&` in what you said.

### Encryption (vault)

The crypto itself held up: BIP39 matches the reference vectors, scrypt is used correctly, ECIES binds both keys, and WWENC1 chunks can't be reordered, truncated or swapped between files. SQLCipher gets its key only by pragma. The findings were in what happens around unlock:

| Finding | Status |
|---|---|
| **High:** a planted `vault/migration.json` made the next ordinary unlock decrypt everything, or delete `vault.json`, with no reauth | **Fixed.** The journal is signed with a key from the master key, and an unsigned one is dropped at unlock with a notice. `forgetVault` runs only when the disk proves nothing is still encrypted, and only after the inbox is imported. |
| **High:** DevTools on the lock screen could plant code that captures the password, or reads history after unlock | **Fixed** (see H11). |
| **Medium:** Touch ID quietly re-enrolled after a fingerprint change, so a finger added by someone who knows the Mac password got in | **Fixed.** Touch ID turns off and says why; turning it back on needs the password. The helper reports "invalidated" only for a key that is really gone. |
| **Medium:** `vault.json` prefs could be flipped offline (for example "keep notes readable", or no lock on sleep), and changed over IPC while locked | **Fixed.** Prefs are signed and checked at unlock; every change needs the unlock; until checked, notes are sealed. |
| **Medium:** a swapped sealing key went unnoticed | **Mitigated.** It's restored at unlock and the user sees a notice. Remainder: items sealed while locked to the swapped key are readable by whoever swapped it. Pinning the key needs a signed build (Keychain). |
| **Medium:** planted sealed files were trusted: Memory swap rules that rewrite dictations, inbox items overwriting recording #42, and plain copies read instead of sealed ones | **Mitigated.** Inbox ops accept only stand-in ids and checked field types, a plain copy of an always-sealed store is never read, and the threat-model text now admits whole-file substitution and rollback. |
| **Medium:** passwords of 8 characters with no check, and no backoff | **Mitigated.** Common passwords are refused (114-entry list) and failed unlocks back off up to 30 s. The minimum length is still 8. |
| **Low:** Memory IPC handlers answered while locked; rotation keys survived a lock; secrets weren't zeroed; recovery-phrase copy fell back to an unmarked write and could reach an iPhone over Universal Clipboard; the Touch ID prompt text came from the caller; recover while unlocked force-locked on a wrong phrase; the dictionary went to localStorage before the vault status was known | **Fixed.** |
| **Info:** scrypt parameters in `vault.json` could freeze the app; a DB handle leaked on a wrong key | **Fixed** (capped, closed). |

### Words in images and ⌘K search (v2.4.0, reviewed after it merged)

v2.4.0 reads the text in clipboard images with Apple Vision (opt-in) and adds a ⌘K box that searches everything. Reviewed after it merged into this branch. Most of it held up:
- The reader resolves every path with `resolveAppFile`, and a plain copy is refused while encryption is on.
- Image bytes are piped to the helper and never written; decrypted bytes are wiped after the answer.
- The helper is killed before the keys go on lock.
- The helper's frames are bounded, and its arguments are an array (no shell).
- All SQL is parameterized; LIKE escapes `%`, `_` and `\`; queries and limits are capped.
- Snippets render as React text, not HTML.
- A trigger deletes an image's words with its entry, and the secure delete from this review covers the new table.

| Finding | Status |
|---|---|
| **Medium:** a screenshot of an API key, token, private key, card number or recovery phrase made the secret searchable text. It showed in search snippets and in Look closer, while the same secret copied as text is never kept. | **Fixed.** `redactSecrets` (`clipboard-pure.js`) stores those as `•••••`, along with single words shaped like a password or a random key. It uses the same detectors as copied text, applied to the parts of a longer text. Words read by v2.4.0 are redacted once at the next start (`bf_image_text.redacted`, `redactStoredImageText`; about 0.6 s for 13,000 images). The image itself is kept, as before. |
| **Low:** the OCR helper got the app's whole environment, including API keys from `.env` | **Fixed.** It gets `buildSidecarEnv`, like every other child process. |
| **Low:** turning Words in images off deleted the words, but their old pages stayed in the WAL until SQLite's next checkpoint | **Fixed.** Off, and the cleanup at attach, run `wal_checkpoint(TRUNCATE)` after deleting. |
| **Low:** a helper that sent output without a newline was buffered in main, without a limit, until the 60 s read timeout | **Fixed.** Over 1 MB without an answer, the helper is stopped and the image counts as a crash. |
| **Info:** History's search moved from FTS `MATCH` to `LIKE` | **Checked.** `search-pure.js` (this review's FTS query escaping) is removed, since nothing uses it now. |

## Verified by attack

| Attack | Before | After |
|---|---|---|
| One WebSocket message with a 16-byte header and a 1 MB body to sherpa's offline server | `Segmentation fault` (exit 139) | Closed with "Invalid header", server keeps working |
| Browser-style `Origin` on the sherpa WebSocket | Accepted | HTTP 400 at handshake |
| Where sherpa listens (`/proc/net/tcp`) | `00000000` (all interfaces) | `0100007F` (127.0.0.1) |
| `ELECTRON_RUN_AS_NODE=1 WhisperWoof -e '…'` | Runs the code | Doesn't |
| `strings transcriptions.db` after deleting a copied password | Password found (row and FTS index) | Not found |
| llama-server `/slots`, `/v1/chat/completions` without the key | 200 | 401 |
| whisper-server `/load` with `model=/etc/passwd` | Server exits | 404 |

## What still needs you

1. **Claim the `@whisperwoof` npm scope.** The built-in plugins run `npx @whisperwoof/todoist-mcp` (and TickTick, Notion, Calendar, Slack). That scope is unregistered today, so anyone could publish those names. The Allow dialog would show the official-looking command, and clicking Allow would run their code. No UI dispatches plugins yet, which is why this is Medium, not Critical. Register the org on npmjs.com, or ship the plugins inside the app.
2. **Check the next macOS release build once.** Three changes can only be proven on a Mac:
   - The patched sherpa servers build on the `macos-14` runner. They need `cmake` (preinstalled there) and add a few minutes. If they fail, the release ships without Parakeet instead of shipping the vulnerable server.
   - The app starts with the new fuses, including asar integrity.
   - Parakeet and live dictation still work.
3. **Developer ID signing** unlocks the rest:
   - API keys can move to the Keychain. The design doc deferred this because unsigned builds prompt after every update.
   - `disable-library-validation` and `allow-unsigned-executable-memory` can be dropped from the entitlements.
   - Cookie encryption can be turned on.
4. **Decide on screen-sharing protection.** History shows recent clipboard text in plain view, and since v2.4.0 the ⌘K box shows clipboard text and images as you type. `setContentProtection` would hide the window from screen shares and screenshots (including yours), so it's your call.

## Accepted, and why

- **API keys in `userData/.env`** stay outside the vault until builds are signed (see 3 above). The file is now 0600, and keys never reach child processes.
- **The whisper-server path prefix is visible in `ps` on Linux** to other local users. whisper-server has no other way to take it. It still stops web pages and DNS rebinding. macOS hides other users' arguments.
- **GitHub digests come from the same GitHub response.** They stop tampering in transit, not a compromised release. A signed manifest would.
- **Clipboard copies from your iPhone (Universal Clipboard)** are still captured. iOS password managers can't mark them, so the secret detector is what protects them.
- **`xdotool type` on Linux** has the typed text in its arguments for as long as it types.
- **Words in images:**
  - A password that doesn't look like one ("hunter2") still becomes searchable when it's in a screenshot. The consent panel says so, and turning the feature off deletes every word.
  - The OCR helper isn't sandboxed. It parses the same images main already decodes with the same macOS image libraries, so it adds no new kind of parser. A `sandbox_init` no-network profile needs testing on a Mac first, because a sandbox that breaks Vision would mark every image failed.
- **Vault remainders:**
  - The password minimum is still 8 characters (common passwords are refused).
  - scrypt still runs on the main thread (about 0.5 s per try).
  - Sealed files have no author MAC, so a file planted or rolled back while locked can still be read as genuine. Memory rules and inbox items are checked instead.
  - A `vault.json` written by 2.3.0 has no prefs MAC yet, so its first unlock can't tell a deleted MAC from an old file.
  - Binding the Secure Enclave key to the app needs Developer ID signing.
- **Malware already running as you while unlocked** can read the screen, the process memory and IPC, as the encryption design says.
